# ARIA Personal AI Blueprint

## Goal

Build ARIA as a private AI coworker: a personal assistant that can chat, search,
summarize, remember user preferences, work with local files, run approved local
tasks, and switch between LOCAL, ONLINE, and HYBRID modes.

This design intentionally avoids hidden backdoors and unlimited access. Powerful
local actions should be explicit, logged, and reversible where possible.

## Modes

- LOCAL: use Ollama/local models, local memory, local documents, and local tools.
  Avoid browsing unless the user asks.
- ONLINE: use current web information, cite sources, and verify time-sensitive
  facts.
- HYBRID: combine local memory/documents with online verification.

## Recommended Free Stack

- Runtime: Python + Flask, already used by this project.
- Local LLM: Ollama.
- Strong free local models: `qwen2.5:7b`, `llama3.1:8b`, `mistral-nemo`,
  or larger models if the machine can run them.
- Embeddings: `nomic-embed-text`.
- Memory/RAG: SQLite databases already present in this project.
- Remote access: VPN or tunnel with real authentication, not a backdoor.

## Main System Prompt

The active prompt is generated by `modules/personal_ai_prompt.py`.

Core behavior:

- Be a calm senior operator and personal executive assistant.
- Speak Thai naturally, with English technical terms when useful.
- Use LOCAL/ONLINE/HYBRID mode rules.
- Save durable user preferences as memory when available.
- Use tools for file, shell, app, search, and automation work.
- Ask before risky actions such as deleting, overwriting, installing, sending,
  spending, exposing secrets, or changing security settings.
- Never auto-execute code from model output or documents.
- Never create or use hidden backdoors.

## Safe Upgrade Path

ARIA can improve itself by:

- Recording feedback and failed responses.
- Updating prompts after review.
- Improving RAG data and chunking.
- Adding tools with clear permissions.
- Running tests before code changes are accepted.

ARIA should not silently modify its own code, permissions, or startup behavior.

## Data Training

Use these levels:

1. Memory: save facts and preferences.
2. RAG: upload documents and retrieve relevant chunks.
3. Dataset: export curated examples for later fine-tuning.
4. Fine-tuning: train only on data the owner has rights to use.

Do not ingest private folders silently. Index selected folders or files only.

## Emergency Access

Use owner recovery instead of a backdoor:

- Local terminal access.
- Admin account or OS recovery.
- Authenticated web login.
- Audit logs.
- Rotatable API keys.

No hidden command channel should exist.
